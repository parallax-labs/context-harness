Start with one project question

“How does authentication work here, and which decisions explain it?”

Configure a read-only project researcher to search your indexed files and cite the sources it uses. Read its answer, then inspect the run to see the recorded model and tool activity.

After completing the project researcher setup, run these commands from that project's root. Agent execution uses your configured model.

ctx agent validate
ctx tool bindings validate
ctx init
ctx sync filesystem:project
ctx search "authentication" --source "filesystem:project"
ctx agent run project-researcher "How does authentication work here? Cite the files you use."
ctx agent history --limit 5

Use the run ID from history with ctx agent inspect <run-id>. If direct search finds no relevant documents, check the source configuration and sync before asking the agent. Review the answer and citations; a completed run is not a guarantee of correctness.

Before you start

Do I need to run an agent to use Context Harness?

No. You can index and search project documents from the CLI, or expose them over MCP to an existing AI client. Profiles provide reusable starting instructions; the external client owns execution and permissions.

Does local storage mean all processing stays on my machine?

No. The index and run history are local. Cloud model providers, external AI clients, connectors, and tools may send data over the network. Use local models and appropriately configured tools when processing must stay local.

Can I use Claude?

A compatible Claude client can use Context Harness context and profiles over MCP. The built-in agent runtime currently includes OpenAI and Ollama generation adapters. It does not include a native Anthropic generation adapter.

Can a webhook start an agent?

Your application can receive a webhook and submit a durable task through the CLI or host APIs. Context Harness does not currently provide a built-in webhook receiver. Your application supplies verification, event filtering, and result delivery; a separately started worker executes accepted tasks.

What happens when a run is interrupted or needs input?

Eligible interrupted runs can resume after recovery checks. Eligible standalone runs suspended as blocked or needing input can be continued explicitly. Changed definitions, uncertain tool effects, MCP-backed runs, and delegated runs can restrict recovery. Consult the lifecycle documentation for the supported cases.
