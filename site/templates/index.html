Before you build

Is this a context layer or an agent runtime?

Both. Context Harness provides searchable context and an optional runtime for executing agents with selected tools. Use that runtime directly or inside an application, or expose context to an existing AI client over MCP.

Can agents use live information and take actions?

Yes, through configured tools and permitted operations. The runtime includes support for selected stdio MCP tools. External-service compatibility depends on the server and authentication setup; direct remote MCP transports and OAuth are not provided by this client path yet.

Can a webhook trigger work?

Your application can receive and verify a webhook, filter the event, and submit a durable task. Context Harness does not provide a built-in webhook receiver. A separately operated worker executes accepted work; your application owns result delivery and publication policy.

Do I need a separate database service?

No. Context Harness stores its knowledge index and runtime history in SQLite, with no separate database service required. Configured models, clients, connectors, and tools may send data over the network. Local storage does not mean every operation stays on the machine.

Does search automatically refresh files or apply repository instructions?

No. Search uses the indexed material; sync configured sources when you need to refresh them. Including AGENTS.md or CLAUDE.md makes those documents searchable, but does not automatically apply their rules. The client or workflow must load the applicable guidance.

Do permissions and history mean every run can recover safely?

No. Eligible interrupted runs can resume after recovery checks, but not every run is resumable. MCP-backed runs currently do not support resume. Inspect external state before repeating an operation whose outcome is uncertain; recorded activity is not a guarantee of correctness or exactly-once effects.

Can I use Claude or another existing assistant?

A compatible client can use Context Harness over MCP while keeping its own model and execution controls. The built-in runtime does not currently include a native Anthropic generation adapter. Client integration and runtime provider support are different paths.

Will this reduce token costs?

Focused retrieval can reduce how much material you choose to include, but savings depend on the task, model, client, and tool responses. Embedding reuse and model-input token costs are separate. Compare representative workflows; no fixed reduction is promised.
